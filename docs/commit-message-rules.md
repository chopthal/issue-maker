📄 커밋 메시지 작성 규칙 (Commit Message Rules)

1\. 구조 및 형식

모든 커밋 메시지는 아래의 표준 형식을 엄격히 따릅니다.

<접두사>: <핵심 요약 (한 줄)>

\- <개발 항목 1>

\- <개발 항목 2>



2\. 업계 표준 접두사 (Type)

반드시 아래의 접두사 중 하나를 선택하여 소문자로 시작합니다.

• feat: 새로운 기능 추가

• fix: 버그 수정

• chore: 빌드 업무, 패키지 매니저 설정, 자잘한 스타일 수정 등 (코드 변경 없는 경우)

• docs: 문서 수정 (README.md, API 주석 등)

• style: 코드 의미에 영향을 주지 않는 변경 (포맷팅, 세미콜론 누락 등)

• refactor: 코드 리팩토링 (기능 추가나 버그 수정이 없는 구조 변경)

• test: 테스트 코드 추가 및 수정



3\. 작성 핵심 원칙

• 간결성: 제목(첫 줄)은 50자 이내로 어떤 작업을 했는지 명확하고 핵심만 요약합니다.

• 완전성: 구현하거나 수정한 개발 항목은 절대 누락하지 않고 모두 명시합니다.

• 개조식 본문: 세부 개발 항목은 본문에 하이픈(-)을 사용한 개조식 단답형으로 작성합니다.

• 명사형 종결: 각 줄의 끝은 명사형(\~추가, \~수정, \~삭제)으로 간결하게 끝맺습니다.

• 언어: 모든 메시지는 한글로 작성하되, 고유 명사나 변수명/메서드명은 영문을 유지합니다.



4\. 올바른 작성 예시

feat: 사용자 로그인 기능 구현 및 유효성 검사 추가

\- 이메일 및 비밀번호 입력 필드 UI 구현

\- JWT 토큰 기반 인증 로직 추가

\- 이메일 형식 미일치 시 에러 메시지 표시 기능 추가
